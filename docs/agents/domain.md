# Domain docs

This repo uses a single domain context.

Before exploring domain behavior, read the root GLOSSARY.md.
Use its vocabulary in specifications, issues, code and tests.

Before designing or changing behavior, read relevant decisions
under docs/adr/, when present. Surface conflicts with an existing
decision explicitly.

Continue when optional domain documents are absent. Create new
terms or decision records when the work establishes them.

For Android UI work, follow docs/ui-guidelines.md.
For persistence changes, follow app/schemas/README.md.
